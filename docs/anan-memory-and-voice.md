# 安安的個人記憶與語音邀請

## 個人記憶

安安保留原有的整體印象、好感度與專用稱呼，並在每次批次整理互動時，另外記錄：

- `preference`：有依據的偏好。
- `promise`：對話明確支持的約定。
- `event`：具體互動與往事。
- `recent`：暫時情緒與尚未結束的話題，更新後七天過期。

每條記憶保存來源片段、片段時間、更新時間與 `explicit`（明確提及）或 `inferred`（推測）。修正與刪除必須引用同一個人的新片段；舊記憶不會僅因再次被讀取而延長有效期。原有印象仍為最多 500 字元的摘要。資料以伺服器與使用者隔離，每人最多保留 100 條新式個人記憶。

回覆時以當下文字的中英文詞彙／中文雙字匹配，優先挑選相關記憶，再考量近期狀態、重要性與時間，最多放入六條。這是第一版文字匹配，尚不具備向量語意檢索；同義詞不一定能匹配。原始證據保存在資料庫，不會整批塞入回覆提示。

可使用以下指令，結果只顯示給本人：

- `/安安個人記憶`：查看自己的個人記憶與近期狀態。
- `/安安忘記個人記憶 記憶編號`：刪除指定記憶；這不會一併清除整體印象，也不會禁止之後的新互動再次形成記憶。

SQLite 在程式啟動時自動建立新表，原有資料保留。新記憶從之後整理的互動片段開始形成，不會把舊印象虛構拆解成往事。預設仍是每十次成功回覆整理一次；摘要輸出預算增加到 4000 tokens。

## 邀請安安上線

1. 自己先加入一般語音頻道。
2. 在允許安安回覆的伺服器直接提及她，或回覆她的訊息，例如「@安安，上線陪我吧」。
3. 安安在一般回覆的同一次模型請求中，依人格、印象、記憶與相處狀態決定接受或拒絕。
4. 她接受時，程式實際加入邀請者原本所在的語音頻道。若邀請者換頻道、頻道已滿、權限不足、安安已在語音或連線失敗，程式不會把她移到其他頻道，並在執行失敗時改回覆實際狀態。

這個流程只處理直接對話中的新邀請；群聊插話、舊邀請與單純討論上線不應觸發。是否構成邀請由模型依語意判斷，程式另外強制限制直接對話、可加入頻道、頻道身分與冷卻時間。沿用既有伺服器、身分組與 AI 請求限額設定。

`config/settings.toml` 的 `[ai.media]`：

- `voice_invitations_enabled = true`：開放一般使用者透過對話邀請安安，自主選擇接受。
- `voice_invitation_cooldown_seconds = 300`：每個伺服器的加入嘗試冷卻五分鐘；管理員送她離開後也會進入冷卻。

原本管理員 `/上線` 和 `/滾` 仍可使用。此功能不會定時自行加入，也沒有新增收聽或語音辨識；加入時使用自我拒聽。既有 TTS 功能依原設定運作。

修改完成後需重啟機器人，讓新程式、資料表與斜線指令同步生效。

## 驗證

使用 unittest 驗證個人記憶來源、跨使用者與伺服器隔離、更新、刪除、去重、到期排除、相關性檢索，以及模型回覆串接、語音加入競爭、拒絕、權限、換頻道、頻道滿員、失敗回饋與啟動流程。測試使用模擬 Discord／模型，不會向真實頻道發送訊息或加入語音。
