# 安安的個人記憶與語音邀請

## 個人記憶

安安保留原有的整體印象、好感度與專用稱呼，並在每次批次整理互動時，另外記錄：

- `preference`：有依據的偏好。
- `promise`：對話明確支持的約定。
- `event`：具體互動與往事。
- `recent`：暫時情緒與尚未結束的話題，更新後七天過期。

每條記憶保存來源片段、片段時間、更新時間與 `explicit`（明確提及）或 `inferred`（推測）。修正與刪除必須引用同一個人的新片段；舊記憶不會僅因再次被讀取而延長有效期。原有印象仍為最多 500 字元的摘要。資料以伺服器與使用者隔離，每人最多保留 100 條新式個人記憶。

回覆時以當下文字的中英文詞彙／中文雙字匹配，優先挑選相關記憶，再考量近期狀態、重要性與時間，最多放入六條。這是第一版文字匹配，尚不具備向量語意檢索；同義詞不一定能匹配。原始證據保存在資料庫，不會整批塞入回覆提示。

管理入口統一為 `/安安管理`，僅限伺服器管理員使用。面板與結果只顯示給操作者；每個按鈕、選單與表單都重新檢查操作者、伺服器及管理員權限。一般成員無法查看或刪除記憶，包括自己的記憶。

- 成員概況：先選擇成員，查看整體印象、好感度並開啟表單調整好感度。切換功能仍保留選定成員。
- 個人記憶：每頁五條，可選擇一條記憶並確認刪除。確認畫面固定原本的成員與記憶；記憶若已更新則拒絕刪除，需重新整理。刪除不會一併清除整體印象，也不會禁止之後的新互動再次形成記憶。
- 伺服器記憶：分頁查看、選取並確認刪除共同記憶。
- 語音控制：加入操作者所在頻道、離開語音，或填寫文字與語言讓安安朗讀。

面板閒置十分鐘後過期，可重新執行 `/安安管理`。原本的印象、個人記憶、伺服器記憶、管理好感度、上線、滾、洗腦等九個管理指令已整併移除；一般成員的專用稱呼、查看自己好感度與傳話筒指令保留。

SQLite 在程式啟動時自動建立新表，原有資料保留。新記憶從之後整理的互動片段開始形成，不會把舊印象虛構拆解成往事。預設仍是每十次成功回覆整理一次；摘要輸出預算增加到 4000 tokens。

## 邀請安安上線

1. 自己先加入一般語音頻道。
2. 在允許安安回覆的伺服器直接提及她，或回覆她的訊息，例如「@安安，上線陪我吧」。
3. 安安在一般回覆的同一次模型請求中，依好感度配合意願、人格、印象、記憶與相處狀態決定接受或拒絕。
4. 她接受時，程式實際加入邀請者原本所在的語音頻道。若邀請者換頻道、頻道已滿、權限不足、安安已在語音或連線失敗，程式不會把她移到其他頻道，並在執行失敗時改回覆實際狀態。

這個流程只處理直接對話中的新邀請；群聊插話、舊邀請與單純討論上線不應觸發。是否構成邀請由模型依語意判斷，程式另外強制限制直接對話、可加入頻道、頻道身分與冷卻時間。沿用既有伺服器、身分組與 AI 請求限額設定。

`config/settings.toml` 的 `[ai.media]`：

- `voice_invitations_enabled = true`：開放一般使用者透過對話邀請安安，自主選擇接受。
- `voice_invitation_cooldown_seconds = 300`：每個伺服器的加入嘗試冷卻五分鐘；管理員送她離開後也會進入冷卻。

管理員強制上線與離開功能位於 `/安安管理` 的「語音控制」。受邀上線功能不會定時自行加入，也沒有新增收聽或語音辨識；加入時使用自我拒聽。既有 TTS 功能依原設定運作。

### 好感度與配合意願

聊天中的請求與語音邀請會套用以下意願，與既有「是否回覆」的機率判斷分開：

| 好感度 | 配合意願 |
| --- | --- |
| −100～−51 | 很低，額外邀請通常婉拒 |
| −50～−11 | 偏低，較猶豫，但仍可能接受體貼且不費力的請求 |
| −10～20 | 普通，按請求與情境決定 |
| 21～50 | 偏高，通常願意接受合理且不費力的請求 |
| 51～80 | 很高，優先考慮答應，願意多花心力 |
| 81～100 | 最高，通常樂意答應，仍可拒絕 |

這是明確傳給模型的行為引導，沒有額外擲骰或保證固定接受率。印象、近期狀態與請求負擔仍參與判斷；一般事實提問不會因低好感故意答錯。斜線指令仍依原本權限執行，權限與頻道可加入條件不受好感度影響。

修改完成後需重啟機器人，讓新程式、資料表與斜線指令同步生效。

## 日文朗讀

MiniMax TTS 支援頂層參數 `language_boost: "Japanese"`，用來加強日文辨識。
原本請求沒有帶語言提示，純漢字短句容易存在中日文歧義；語言提示不是翻譯，也不是所有讀音都正確的保證。
參見 [MiniMax T2A HTTP 官方文件](https://platform.minimax.io/docs/api-reference/speech-t2a-http)。

- `/安安管理` → 語音控制 → 朗讀文字，可填寫「語言」，日文漢字請明確填「日文」，例如文字「世界」、語言「日文」。
- AI 回覆透過 `tts_language` 標記實際朗讀語言；要求日文讀法時使用 `Japanese`，中文回覆使用 `Chinese`，英文使用 `English`，其他語言或無法指定單一語言的混合內容使用 `auto`。
- 固定的日文語音問候明確指定 `Japanese`。
- `[tts].language_boost` 是未指定時的預設，維持 `auto`；可以設定為 `Japanese`，但個別指令與 AI 回覆的語言標記會優先。
- 快取鍵包含語言；相同漢字的中文、日文不共用音檔，新鍵也不會命中修改前的舊音檔。無須刪除整個快取目錄。

日文提示的實際發音效果仍需使用目前音色試聽，尤其是姓名、地名與多種讀法的漢字。

## 驗證

使用 unittest 驗證個人記憶來源、跨使用者與伺服器隔離、更新、刪除、去重、到期排除、相關性檢索，以及模型回覆串接、語音加入競爭、拒絕、權限、換頻道、頻道滿員、失敗回饋與啟動流程。測試使用模擬 Discord／模型，不會向真實頻道發送訊息或加入語音。
